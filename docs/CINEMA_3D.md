# Cinema 3D — first release

## Direction contract
THESIS: A small cinema the viewer can explore and choose a seat in before watching with friends.
OWN-WORLD: Preserve CineMind typography and the current player. Cinema-only charcoal walls, red-black supplied chair, warm aisle strips and restrained cool diagonal wall lights follow the supplied room photograph.
STORY: Create or join the existing protected room, choose a seat (including the host), confirm, enter the existing player. Room 3D returns to the same seating state.
FIRST VIEWPORT: Interactive auditorium fills the available space, an unobtrusive title at top left, camera controls at bottom, compact seat plan and confirmation at right. On phones the seat plan sits below the auditorium.
FORM: User-specified auditorium, code-led extension; no concept seed needed for this pinned layout. Demo uses 32 regular seats and 4 VIP seats and 12 explicitly illustrative members.
Review: the user is checking the experience manually from screenshots; no automated tests or browser screenshot passes were requested.

## Assets
The original GLB and two reference images were supplied by the user and remain in the local public/3d folder. This PR ships only the two optimized GLBs required at runtime. Supply the originals locally to run the optimization script. `npm exec -- node scripts/optimize-cinema-chair.mjs` produces a separate simplified, texture-resized GLB. The runtime shares chair geometry/materials via InstancedMesh; procedural seats remain usable while loading or if the optimized asset fails.

## Behavior
`/watch-party/demo-3d` is an unauthenticated visual preview, with clearly labeled fixture occupants. Actual rooms use the existing authentication/password/capacity checks before seat selection. The physical layout is fixed: 32 regular seats A1-H4 plus four VIP recliners V1-V4 on the rear platform, total 36. Membership limits never increase the physical seat count.

Seat reservations live separately from the room JSON. Redis executes claim/move/expiry atomically so room writes cannot overwrite them. Local development uses equivalent synchronous in-memory transitions. Explicit leave releases the seat when the member has no other screen connected; disconnect holds the seat for 90 seconds. Connected clients renew every 30 seconds. Room deletion removes the seat key. Monotonic revisions reject late snapshots. After a background tab sleeps beyond the grace period, the user may need to select a new seat.

Real rooms project the active episode HLS source onto the 3D screen using a video texture, including during seat selection. Playback follows the room timestamp and play/pause state. The host has explicit play/pause controls; sound is local and initially muted. Opening Room 3D unmounts the main player; returning destroys the 3D video and synchronizes the existing player to the room. Navigation sends no room-wide pause. Autoplay restrictions expose a tap-to-play control. Sources use the same direct/proxy candidates as the main player; iframe-only sources cannot be projected and retain access through the main player. The standalone demo has no movie source. Actual source playback and CORS still need user verification; no automated or browser tests were run for this iteration.

The existing socket service must be restarted/deployed together with the web update. Live multi-account Firebase/password/provider tests are separate from fixture and unit validation.

## Camera modes
Overview orbits the auditorium and allows clicking seat markers. Screen mode isolates the projection surface so chairs and labels cannot obstruct it; wheel/pinch zooms with a fixed centered direction. Seat mode fixes the eye at the selected chair, allows full horizontal look-around and limited vertical head rotation, and changes lens field of view on wheel/pinch. Shift + arrow keys look around from the focused seat canvas; plus/minus zoom. Reset restores the current mode, not the overview. Video rendering follows decoded frames and suspends canvas rendering while the document is hidden.

## Header controls and seated view
Seat/avatar label sprites use an overview-only camera layer; seated and screen views do not display floating seat labels. Picking uses the same marker layer in overview. The cinema header now contains compact playback, sound, seek, resync, chat, microphone, voice speaker, host voice permission, people, invite link, episode and more controls. Chat reuses the existing room ChatPanel, send handler, permissions, unread state and voice provider; desktop chat temporarily replaces the seat map and mobile chat opens above the auditorium. Closing chat restores the seat map without remounting the 3D scene. More includes friend invitations and room reactions. Existing tier and host restrictions remain in effect. Window expansion keeps the header and room tools available. This iteration follows user screenshots; no tests or live browser checks were run at their request.

## VIP and viewing update
The supplied Meshy recliner is preserved; cinema-vip-chair.optimized.glb is a separate 937,636-byte / 23,280-triangle derivative. Regular and VIP models have separate shared instanced geometry. VIP seats are wider, ivory, on a rear platform with gold trim. Seated avatars are small, depth-tested sprites below eye level; overview badges remain overhead.
Screen mode requests native fullscreen (CSS fallback), fits the video's aspect ratio and hides the seat map. Pointer movement brings controls back; Escape or the fullscreen button exits. Speaker chips are drawn from LiveKit active-speaker state. Newly received chat messages float up for three seconds, limited to three visible messages, without replaying chat history on entry.
VIP claims require a freshly checked Ultra entitlement on the server. Voice room join tokens can subscribe but cannot publish. An explicit authenticated microphone request checks host permission, active membership, Ultra and a confirmed V1-V4 seat before updating the existing LiveKit participant's microphone grant. Moving to a regular seat revokes publishing; a five-second reconciliation checks active grants against seat expiry, disconnection and entitlements. Everyone in an enabled room can listen; only VIP Ultra members publish. Revocation still depends on provider availability; failed provider calls are retried. No deployment to Render was performed.
